# 001 — 构建通过不等于功能存在

## 摘要

一次例行盘点发现三处「代码在、功能不在」的缺口：RSS 处理器写成 `const _GET` 从未被导出（且没有任何路由文件），`Head.astro` 用 `new Date(undefined)` 给列表页生成了 `Invalid Date` 的 `article:published_time`，`[type]/[...page].astro` 顶部残留的调试 `Astro.redirect()` 与 `console.log` 在预渲染下被静默忽略。

三者的共同系统条件是：**项目没有任何能观测「路由是否真的产出/元信息是否合法」的反馈回路**。`astro check` 只查类型，`astro build` 只查能否编译，二者都不会因为「端点没导出」「日期是 Invalid」而变红。缺失的是运行期/产物级的校验，而不是某一次疏忽。

## 影响

- RSS 自引入 `@astrojs/rss` 起从未产出，`vercel.json` 却已为 `/feed` 配置缓存头，订阅者长期拿到 404
- 所有列表、标签、归档页向搜索引擎输出 `article:published_time="Invalid Date"`，文章页输出本地化字符串而非 ISO 时间
- 构建日志被调试 `console.log` 持续污染（`[ 'blog' ]`），掩盖真实告警
- 4 个文件/端点为纯死代码（阅读时长桩、零引用组件、空壳端点、孤立工具），增加阅读成本

## 根因分析（blameless）

贡献因素（无单一根因）：

1. **门禁只覆盖「能编译」**：`check` + `lint` + `build` 三件套没有一项检查路由产物或 SEO 元信息的**内容合法性**；`_GET` 未导出与 `new Date(undefined)` 都能让三者全绿。
2. **Astro 的失败模式是沉默的**：路由文件缺少 `export const GET` 不会报错，只是不生成；`Astro.redirect()` 在 `prerender = true` 的页面里被忽略而不告警——两个反馈通道都不存在。
3. **缺少测试**：backlog A2（引入 Vitest）长期待办，纯函数与端点没有回归断言，「改了没坏」无从验证。
4. **注释代替删除**：`read-time` 相关代码以注释形式长期存活，让「未启用」与「已实现」在阅读时不可区分。

## 做得对的地方

- 盘点是**实测**而非读码推断（实际构建、实际请求 `/feed`），避免了第二轮误判
- 文档体系（Float 结构）已存在，缺口一旦定位就有明确的落点：backlog + postmortem + CHANGELOG

## 教训

1. 端点与路由必须**实际请求一次**才算完成——构建绿灯不能证明功能存在。
2. 时间戳类元信息在构造前校验合法性，否则会把 `Invalid Date` 直接写给搜索引擎。
